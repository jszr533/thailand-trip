## Bug 修复：城市指南入口泄漏（commit deaaece，双源同步，待推送）
用户反馈"首页还有入境须知和该城市交通指南，应该是城市页点到城市才显示"。
根因定位：入境须知/交通须知只在 `pagePoints`(城市指南) 渲染，由 `openCity(name)` 触发 `setFlow('points')` 显示；但 `setFlow` 内有一行 `if(f==='points' && !pointsCity){ var c=aggregateCities(); if(c.length) pointsCity=c[0].name; }` —— 当顶部导航「📍 行程点」(`navPoints`) 被直接点击、且尚未选过城市时，会**自动把第一个城市当作默认**并显示其城市指南，绕过"城市页→点城市"这条唯一正确路径。首页地图的点(`openFlowCity`)本就只跳城市页，无泄漏。
修复：① 在 `setFlow` 开头加 `if(f==='points' && !pointsCity){ f='cities'; }`——未选城市时点「行程点」改去城市页让用户先选；② 删除原来的"自动默认第一城"逻辑。
验证：qa_runtime 新增断言"setFlow('points') 无选中城市→body 为 flow-cities 而非 flow-points（不暴露默认城市指南）"通过；已选城市(曼谷)时仍正常进入 flow-points；qa_deep 50 项 0 错误。
注：首页本身 HTML 只有 hero 标题 + 地图模块，从无入境须知/交通须知 DOM；用户看到的"首页上的指南"实为从首页顶部导航点「📍 行程点」直接跳进的默认城市指南。
